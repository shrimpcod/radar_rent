# Модуль парсеров

Модуль для сбора объявлений об аренде жилья с внешних источников (ЦИАН, Авито и др.)
и сохранения их в базу данных.

---

## Архитектура

```
parsers/
├── base/
│   ├── base_parser.py   # Абстрактный базовый класс
│   └── http_client.py   # HTTP клиент с имитацией браузера
├── cian/
│   ├── parser.py        # Парсер ЦИАН
│   ├── config.py        # URL и payload для API ЦИАН
│   └── mapper.py        # Маппинг JSON ответа → словарь для БД
├── avito/               # Заготовка под будущий парсер Авито
└── utils/
    ├── proxy.py         # Менеджер пула прокси
    ├── retry.py         # Повтор запроса при ошибке
    └── delays.py        # Случайные задержки между запросами
```

Каждый новый источник добавляется как отдельная папка с тремя файлами:
`parser.py`, `config.py`, `mapper.py` — и наследует `BaseParser`.

---

## Как работает парсинг

1. APScheduler в `backend/app/main.py` запускает `fetch_and_save_leads()` каждые 5 минут
2. `CianParser.fetch_listings()` делает запрос к API ЦИАН через `http_client.py`
3. Каждое объявление проходит через `mapper.py` — преобразуется в словарь
4. `cian_parser_service.py` проверяет: объявление новое и свежее (не старше 15 минут)?
5. Если да — сохраняет в БД, отправляет уведомление в Telegram и WebSocket на фронтенд

## Ключевые технические решения

### HTTP клиент: curl_cffi вместо httpx

```python
AsyncSession(impersonate="chrome120", proxy=proxy, timeout=30)
```

ЦИАН защищён от ботов через анализ TLS-fingerprint. Обычные библиотеки (`httpx`, `requests`)
имеют характерный TLS-отпечаток, по которому сервер определяет что запрос не из браузера
и возвращает пустой ответ `200 OK` без данных.

`curl_cffi` имитирует точный TLS-fingerprint браузера Chrome — сервер не отличает
запрос от реального пользователя.

### Ротация прокси

```python
class ProxyManager:
    def get_proxy(self) -> str | None      # следующий прокси по кругу
    def remove_proxy(self, proxy: str)     # удаляет заблокированный прокси
```

При каждом запросе берётся следующий прокси из пула (round-robin).
Если прокси вернул ошибку — он удаляется из пула.
Если пул опустел — автоматически восстанавливается из `.env`.

Прокси задаются в `.env` через запятую:
```
PROXIES=http://user:pass@host1:port,http://user:pass@host2:port
```

### Exponential backoff (retry)

```python
async def retry(func, max_attempts=5, base_delay=5.0)
# задержки: 5 сек → 10 сек → 20 сек → 40 сек → 80 сек
```

При сетевой ошибке запрос повторяется с увеличивающейся задержкой.
После исчерпания попыток — ошибка логируется, следующий цикл запустится по расписанию.

### Случайные задержки

```python
async def random_delay(min_sec=3.0, max_sec=7.0)
```

Случайная пауза 3–7 секунд между циклами парсинга имитирует поведение человека
и снижает вероятность блокировки по частоте запросов.

### Фильтрация свежих объявлений

```python
time_diff = datetime.now() - parsed_data['published_at']
is_fresh = time_diff <= timedelta(minutes=15)
```

Сохраняются только объявления опубликованные не позднее 15 минут назад.
Это исключает дублирование старых объявлений при каждом запуске парсера.

## Добавление нового источника

1. Создать папку `parsers/новый_источник/`
2. Написать `parser.py` — унаследовать `BaseParser`, реализовать `fetch_listings()` и `parse_offer()`
3. Написать `config.py` — URL и параметры запроса
4. Написать `mapper.py` — маппинг JSON ответа в словарь для БД
5. Добавить поле `source` в маппере (например `'source': 'avito'`)
6. Подключить в `cian_parser_service.py` или создать отдельный сервис

---

## Защита от блокировок

Три уровня защиты работают одновременно:

| Уровень | Инструмент | Защищает от |
|---|---|---|
| TLS fingerprint | curl_cffi chrome120 | Определения бота по заголовкам |
| Смена IP | Ротация прокси | Блокировки по IP адресу |
| Имитация человека | Случайные задержки 3–7 сек | Блокировки по частоте запросов |

## Переменные окружения (.env)

```
PROXIES=http://user:pass@host:port,http://...   # список прокси через запятую
```

Если `PROXIES` не задан — запросы идут без прокси (подходит для разработки).
